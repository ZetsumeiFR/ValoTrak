# Releasing ValoTrak (desktop, with auto-update)

The desktop app auto-updates: each release ships signed installers plus a
`latest.json` manifest, and the installed app checks GitHub for a newer version
on startup.

## How a release works

1. Bump the version in **`apps/web/src-tauri/tauri.conf.json`** (`version`) and
   **`apps/web/src-tauri/Cargo.toml`** (`[package] version`). This version is
   what the updater compares against the installed app.
2. Commit and merge to `main`.
3. Tag and push:
   ```bash
   git tag v0.1.2
   git push origin v0.1.2
   ```
4. The **`.github/workflows/release.yml`** workflow runs on the tag: it builds
   and **signs** the app, generates **`latest.json`**, and publishes a GitHub
   Release with the installers + manifest.

The in-app updater endpoint is:
`https://github.com/ZetsumeiFR/ValoTrak/releases/latest/download/latest.json`
— it resolves to the most recent **published, non-prerelease** release, so the
workflow publishes directly (`releaseDraft: false`). Flip that to `true` if you'd
rather review/publish manually (the update goes live when you publish).

## Signing keys (one-time, already done)

Updates must be signed with a keypair generated by `tauri signer generate`:

- **Public key** lives in `tauri.conf.json` → `plugins.updater.pubkey` (committed).
- **Private key** + password are stored as GitHub Actions secrets
  `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.
- The private key file is kept **out of the repo** (e.g. `~/.tauri/valotrak_updater.key`).

> Losing the private key means existing installs can no longer be updated — back
> it up somewhere safe (password manager / secrets vault).

## First-release caveat

Auto-update only works **from the first release that includes the updater
onward**. Builds prior to that (v0.1.0 / v0.1.1) have no updater and must be
replaced by installing a newer build manually once.

## Building a signed release locally (fallback, optional)

CI is the normal path. To build signed artifacts by hand:

```bash
export TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.tauri/valotrak_updater.key)"
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD=""
cd apps/web && bun run desktop:build
```

This produces the installers plus their `.sig` files under
`src-tauri/target/release/bundle/`. You'd then have to assemble `latest.json`
yourself — which is exactly what the CI workflow automates, so prefer tagging.
